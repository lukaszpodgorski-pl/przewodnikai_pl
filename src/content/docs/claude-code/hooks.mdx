**Poziom:** średni, po [subagentach](/claude-code/subagenci/).
**Wcześniej:** wiesz, jak prosić agenta o coś w CLAUDE.md. Teraz nauczysz się wymuszać rzeczy, których agent nie może pominąć.

Hook to Twoja komenda albo skrypt, który Claude Code uruchamia sam w określonym momencie pracy - na przykład tuż przed użyciem narzędzia albo zaraz po edycji pliku. Zamiast skryptu może to być też wywołanie adresu HTTP, narzędzia MCP, prompt albo agent. Hooki zapisujesz w pliku `settings.json`; można je też dołączyć do definicji skilli, subagentów i pluginów.

Jedna rzecz do zapamiętania: **CLAUDE.md prosi, hook wymusza.**

## Zdarzenia

Zdarzenie to moment, w którym hook się uruchamia. Na tej stronie używasz trzech: `PreToolUse` (zanim Claude użyje narzędzia - tu można je zablokować), `PostToolUse` (zaraz po użyciu narzędzia) i `Notification` (gdy Claude chce zwrócić Twoją uwagę).

Oficjalna referencja wylicza **ponad 30** nazwanych zdarzeń. Najczęściej używane: `SessionStart`, `SessionEnd`, `Setup`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `Notification`, `SubagentStart`, `SubagentStop`, `Stop`, `StopFailure`, `PreCompact`, `PostCompact`.

Pozostałe obejmują między innymi `UserPromptExpansion`, `PermissionRequest`, `PermissionDenied`, `PostToolBatch`, `TaskCreated`, `TaskCompleted`, `TeammateIdle`, `InstructionsLoaded`, `ConfigChange`, `CwdChanged`, `DirectoryAdded`, `FileChanged`, `WorktreeCreate`, `WorktreeRemove`, `PreModelSwitch`, `PostModelSwitch`, `Elicitation`, `ElicitationResult`, `MessageDisplay`.

## Struktura

Konfiguracja ma trzy poziomy: zdarzenie (kiedy), matcher, czyli filtr (dla jakich narzędzi), i sam hook (co uruchomić). Zobaczysz to w przykładach niżej.

**Matcher** to filtr nazw narzędzi. `"*"` albo puste pole oznacza wszystkie narzędzia. `Bash` albo `Edit|Write` to dokładne nazwy (pionowa kreska znaczy "albo"). Jeśli wpiszesz inne znaki specjalne, Claude Code potraktuje matcher jako wyrażenie regularne (wzorzec dopasowania tekstu). Narzędzia z serwerów MCP mają nazwy zaczynające się od `mcp__`, np. `mcp__github__.*`.

**Jak hook rozmawia z Claude Code.** Skrypt dostaje opis zdarzenia jako JSON na standardowym wejściu (stdin); hook HTTP dostaje go w treści zapytania. Odpowiada kodem wyjścia, czyli liczbą zwracaną przy zakończeniu, oraz tekstem: zwykłym (stdout) i komunikatem błędu (stderr).

**Kod 2 blokuje operację** na zdarzeniach, które mogą blokować, a tekst ze stderr staje się powodem blokady. Kod 0 razem z JSON-em daje dokładniejszą kontrolę: pole `hookSpecificOutput.permissionDecision` (`allow`, `deny`, `ask` albo `defer`), `additionalContext` (dodatkowa informacja dla Claude) i `updatedInput` (podmiana argumentów narzędzia).

## Przykład 1: auto-format po edycji (`PostToolUse`)

```json
{
  "hooks": {
    "PostToolUse": [
      { "matcher": "Edit|Write",
        "hooks": [ { "type": "command",
                     "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/format.sh",
                     "args": [] } ] }
    ]
  }
}
```

Konfigurację wklejasz do `.claude/settings.json` w katalogu projektu. Skrypt `format.sh` wywołuje Twój formater na edytowanym pliku, np. `npx prettier --write`. Obecność pola `args` sprawia, że Claude Code uruchamia skrypt bezpośrednio, bez powłoki, więc ścieżki ze spacjami nie sprawią kłopotu.

## Przykład 2: blokada edycji i odczytu `.env` (`PreToolUse`, exit 2)

```bash
#!/bin/bash
# .claude/hooks/block-env.sh
INPUT=$(cat)
FILE=$(echo "$INPUT" | jq -r '.tool_input.file_path // empty')
if echo "$FILE" | grep -qE '\.env($|\.)'; then
  echo "Blocked: pliki .env są chronione" >&2
  exit 2
fi
exit 0
```

```json
{ "hooks": { "PreToolUse": [
  { "matcher": "Edit|Write|Read",
    "hooks": [ { "type": "command",
                 "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/block-env.sh" } ] } ] } }
```

## Przykład 3: powiadomienie desktopowe (`Notification`)

```bash
#!/bin/bash
# .claude/hooks/notify.sh
input=$(cat)
title="Claude Code"
body=$(jq -r '.message // "Needs your attention"' <<< "$input")
seq=$(printf '\033]777;notify;%s;%s\007' "$title" "$body")
jq -nc --arg seq "$seq" '{terminalSequence: $seq}'
```

```json
{ "hooks": { "Notification": [
  { "matcher": "",
    "hooks": [ { "type": "command",
                 "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/notify.sh" } ] } ] } }
```

Sekwencja 777 działa m.in. w Ghostty, Warp i urxvt. W Windows Terminal i iTerm2 zamień `777;notify;%s;%s` na `9;%s` (wtedy bez tytułu).

Konfigurację przejrzysz przez `/hooks`. Hooks działają też wewnątrz subagentów.

:::danger[Hook to Twój kod z Twoimi uprawnieniami]
Hook uruchamia arbitralny kod z Twoimi uprawnieniami. Pliki projektowe wymagają zaufania folderu (workspace trust), ale przed uruchomieniem cudzego repozytorium przeczytaj, co jego hooki właściwie robią.
:::

## Ćwiczenie: 10 minut

:::note[Potrzebujesz]
Przykłady są w składni basha. Skrypt korzysta z programu `jq`, który wyciąga dane z JSON-a - sprawdzisz go komendą `jq --version`. Zapisz skrypt jako `.claude/hooks/block-env.sh` i nadaj mu prawo uruchamiania komendą `chmod +x .claude/hooks/block-env.sh`. Konfigurację JSON wklej do `.claude/settings.json` w katalogu projektu, a potem w `/hooks` sprawdź, czy hook jest widoczny.
:::

1. Dodaj hook `PreToolUse` blokujący `.env` według przykładu 2.
2. Poproś Claude o odczyt pliku `.env`.
3. Sprawdź, że operacja została zablokowana wraz z Twoim komunikatem. Jeśli Claude spróbuje obejść blokadę komendą w terminalu (np. `cat .env`), odmów - ten hook pilnuje tylko narzędzi Read, Edit i Write.

**Zaliczenie:** Claude nie odczytał `.env`, a w terminalu widzisz tekst, który sam wpisałeś do skryptu. Masz gwarancję zamiast sugestii.

**Jeśli nic nie zgrzyta i zostaje czas:** porównaj to z regułą `deny` z lekcji o uprawnieniach. Obie blokują, ale hook daje Ci własny komunikat i możliwość logowania prób.

## Teraz wiesz

- Hook to Twój kod w wybranym momencie cyklu życia sesji, a zdarzeń jest ponad 30.
- Kod wyjścia 2 blokuje operację, a JSON na stdout pozwala sterować decyzją precyzyjniej.
- Hooki z cudzego repozytorium czytasz przed uruchomieniem, bo działają z Twoimi uprawnieniami.
