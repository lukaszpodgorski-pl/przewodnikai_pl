Claude Code świetnie radzi sobie z gitem. Siedem typowych workflow:

- **Commity** - poproś "zrób commit z opisową wiadomością", albo użyj własnej komendy `/commit` z lekcji o [własnych komendach](/claude-code/wlasne-komendy/). Commituj często: co zadanie albo co godzinę.
- **Pull requesty** - "utwórz PR z tytułem i podsumowaniem w trzech punktach". Claude użyje `gh` CLI.
- **Konflikty** - "rozwiąż konflikty merge w tych plikach". Claude czyta i proponuje rozwiązanie.
- **Przegląd** - `/code-review` (alias `/review`) szuka błędów w Twoich zmianach, czyli w diffie (zestawieniu linii dodanych i usuniętych), a zależnie od poziomu także miejsc do uproszczenia. Poziom podajesz po nazwie komendy: przy `low` dostajesz tylko uwagi, których narzędzie jest najbardziej pewne, od `medium` do `max` przegląd obejmuje coraz więcej, a `ultra` uruchamia głębszy przegląd w chmurze. `--fix` od razu nanosi poprawki, `--comment` dodaje uwagi jako komentarze do pull requesta. `/security-review` szuka luk bezpieczeństwa.
- **`gh` CLI** - oficjalne narzędzie GitHuba do pracy w terminalu, mocno zalecane. Bez niego Claude może korzystać z API GitHuba, ale niezalogowane zapytania często trafiają na limity. Zaloguj się poleceniem `gh auth login`. Odpowiednik dla GitLaba to `glab`.
- **GitHub Actions** - `/install-github-app` instaluje aplikację Claude na GitHubie i przygotowuje plik automatyzacji (workflow). Potrzebujesz do tego zalogowanego `gh` i uprawnień administratora repozytorium. Po zatwierdzeniu wystarczy napisać `@claude` w komentarzu do pull requesta albo zgłoszenia (issue), a Claude odpowie i wykona zadanie na serwerach GitHuba.
- **Git worktrees** - worktree to druga kopia robocza tego samego repozytorium w osobnym katalogu, na własnej gałęzi. `claude -w feature-auth` uruchamia Claude w takiej kopii, więc równoległe sesje nie nadpisują sobie plików. Dodatkowo `--tmux` tworzy dla niej sesję tmux (patrz [Interfejs i skróty](/claude-code/interfejs-i-skroty/)), a subagent z ustawieniem `isolation: worktree` dostaje własną kopię repozytorium.

## Ćwiczenie: 10 minut

1. Na gałęzi z małą zmianą uruchom `/diff`.
2. Uruchom `/code-review` i przeczytaj znalezione uwagi.
3. Poproś Claude o commit z opisową wiadomością.

**Zaliczenie:** masz commit, którego wiadomości nie musiałeś pisać, i listę uwag, których sam nie szukałeś. Oceń, ile z nich było trafnych - to Twój punkt odniesienia na przyszłość.

**Jeśli nic nie zgrzyta i zostaje czas:** uruchom `/code-review --fix` na tej samej gałęzi i porównaj, co narzędzie zmieniło samo, a co zostawiło Tobie.

## Teraz wiesz

- Commity, pull requesty i konflikty to zadania, które oddajesz w całości.
- `gh` CLI warto zainstalować od razu: bez niego Claude szybciej trafia na limity GitHuba, a `/install-github-app` go wymaga.
- Worktree to sposób na kilka równoległych sesji bez deptania sobie po gałęziach.

**Następny krok:** [Terminal, IDE i urządzenia](/claude-code/terminal-ide-urzadzenia/) - konfiguracja terminala, wtyczki do edytorów i przenoszenie sesji między urządzeniami.
