MCP (Model Context Protocol) to otwarty standard, przez który Claude łączy się z zewnętrznymi narzędziami i danymi: systemem zgłoszeń (issue tracker), bazą danych, API innej usługi, monitoringiem. Serwer MCP to program, który wystawia Claude gotowe narzędzia - na przykład "pobierz zgłoszenie nr 123". Ty go tylko podłączasz, nie piszesz integracji.

## Dodawanie serwerów

W przykładach `YOUR_PAT` i `KEY` zastąp własnymi kluczami. PAT (personal access token) to osobisty token dostępu, który generujesz w ustawieniach GitHuba. Przy serwerach lokalnych `--` oddziela opcje Claude Code od komendy uruchamiającej serwer - bez niego Claude Code próbowałby czytać flagi serwera, np. `-y`, jako własne.

```bash
# HTTP (zalecane dla zdalnych):
claude mcp add --transport http notion https://mcp.notion.com/mcp
claude mcp add --transport http github https://api.githubcopilot.com/mcp/ \
  --header "Authorization: Bearer YOUR_PAT"

# SSE (wycofywany - używaj HTTP, jeśli serwer go obsługuje):
claude mcp add --transport sse asana https://mcp.asana.com/sse

# stdio (lokalny proces) - pamiętaj o --:
claude mcp add --env AIRTABLE_API_KEY=KEY --transport stdio airtable \
  -- npx -y airtable-mcp-server

# z JSON:
claude mcp add-json weather '{"type":"http","url":"https://api.weather.com/mcp",
  "headers":{"Authorization":"Bearer token"}}'

# import z Claude Desktop (macOS, WSL):
claude mcp add-from-claude-desktop
```

Zarządzanie: `claude mcp list`, `claude mcp get <name>`, `claude mcp remove <name>`, `claude mcp login <name>` i `logout <name>` z shella, a w sesji `/mcp`.

## Zakresy

Zakres decyduje, gdzie zapisuje się konfiguracja i kto ją zobaczy:

- `local` (domyślny) - zapis w `~/.claude.json`, działa tylko w tym projekcie i tylko u Ciebie.
- `project` - zapis w pliku `.mcp.json` w repozytorium, więc trafia do gita i dostaje go każdy, kto pracuje z tym repo.
- `user` - też `~/.claude.json`, ale działa we wszystkich Twoich projektach.

Zakres wybierasz flagą `--scope`, np. `claude mcp add --scope project ...`.

Jeśli serwer o tej samej nazwie jest zdefiniowany w kilku miejscach, Claude Code bierze jedną definicję z najważniejszego źródła, w kolejności: local, project, user, plugin, a na końcu connector z konta claude.ai. Pól z różnych miejsc nie łączy.

## Transporty i uwierzytelnianie

Transport to sposób, w jaki Claude Code rozmawia z serwerem. **stdio** - serwer to program uruchomiony na Twoim komputerze. **HTTP** (streamable-http) - serwer działa w internecie, to zalecany wybór dla serwerów zdalnych. **SSE** - starszy transport zdalny, wycofywany. **WebSocket** (`type: "ws"`) - stałe połączenie w obie strony, ustawisz go tylko przez JSON (`add-json` albo `.mcp.json`).

Zdalne serwery często wymagają logowania przez OAuth (standard, w którym potwierdzasz dostęp w przeglądarce zamiast wklejać hasło). Uruchomisz je przez `/mcp` w sesji albo `claude mcp login <name>` z shella. W nietypowych konfiguracjach przydają się `--callback-port`, `--client-id`, `--client-secret`, `oauth.scopes` i `headersHelper`.

W `.mcp.json` możesz wstawiać zmienne środowiskowe zamiast wpisywać sekrety wprost: `${VAR}` wstawia wartość zmiennej `VAR`, a `${VAR:-default}` wartość domyślną, gdy zmienna nie jest ustawiona.

## Zasoby i prompty

Zasób (resource) to dane, które serwer udostępnia do czytania - na przykład treść zgłoszenia albo schemat tabeli. Wpisz `@`, a obok plików zobaczysz zasoby podłączonych serwerów. Format: `@server:protocol://path`, na przykład `@github:issue://123` albo `@postgres:schema://users`.

Prompt MCP to gotowe polecenie przygotowane przez autora serwera. W menu po wpisaniu `/` widać je jako `/serwer:prompt (MCP)`, a uruchomisz je też jako `/mcp__server__prompt [args]`, na przykład `/mcp__github__list_prs`.

**Tool Search**, domyślnie włączony, odracza definicje narzędzi - dzięki temu dodanie wielu serwerów minimalnie obciąża <Termin id="okno-kontekstowe">okno kontekstu</Termin>.

## Przykład `.mcp.json` (zakres projektu, do commita)

```json
{
  "mcpServers": {
    "db": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y","@bytebase/dbhub","--dsn","${DB_DSN}"]
    },
    "github": {
      "type": "http",
      "url": "https://api.githubcopilot.com/mcp/",
      "headers": {"Authorization":"Bearer ${GITHUB_PAT}"}
    }
  }
}
```

**Claude Code jako serwer MCP:** `claude mcp serve` udostępnia jego własne narzędzia innym klientom.

## Ćwiczenie: 10 minut

1. Dodaj lokalny serwer plikowy, wskazując istniejący katalog, na przykład folder projektu: `claude mcp add --transport stdio filesystem -- npx -y @modelcontextprotocol/server-filesystem /sciezka/do/katalogu`. Zamiast `/sciezka/do/katalogu` wpisz prawdziwą ścieżkę. Na Windowsie bez WSL podaj ścieżkę w stylu `C:\projekty\moj-projekt`, a przed `npx` dopisz `cmd /c` - tak zaleca README serwera.
2. Uruchom `/mcp` i sprawdź, że serwer się połączył.
3. Poproś: "Użyj serwera filesystem i wypisz pliki w tym katalogu".

**Zaliczenie:** `/mcp` pokazuje serwer jako połączony, a Claude wywołuje narzędzie o nazwie zaczynającej się od `mcp__filesystem__` i zwraca listę plików. Masz działającą integrację bez linijki własnego kodu.

**Jeśli nic nie zgrzyta i zostaje czas:** usuń serwer przez `claude mcp remove filesystem` i dodaj go ponownie w zakresie `project`. Zobacz, jak wygląda wygenerowany `.mcp.json`.

## Teraz wiesz

- Serwer dodajesz jedną komendą, a transport wybierasz według tego, gdzie serwer stoi.
- Zakres decyduje o tym, kto jeszcze zobaczy Twoją konfigurację - `project` idzie do repozytorium.
- Zasoby i prompty serwera masz pod `@` i pod ukośnikiem, bez dodatkowej konfiguracji.
