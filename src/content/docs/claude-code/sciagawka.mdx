## Komendy CLI

```text
claude                      # sesja interaktywna
claude "prompt"             # z promptem początkowym
claude -p "prompt"          # tryb print (skrypty, CI)
claude -c   /  --continue   # kontynuuj ostatnią
claude -r "id" "prompt"     # wznów sesję
claude --model opus         # wybór modelu
claude -w feature           # git worktree
claude --bg "task"          # background agent
claude remote-control       # Remote Control, skrót: claude rc
claude update / doctor / install
claude mcp add|list|remove|get|login|logout
claude plugin install <name>@<marketplace>
claude auth login|logout|status
claude setup-token          # token do CI
```

## Ścieżki plików konfiguracyjnych

```text
~/.claude/settings.json                 # user settings
.claude/settings.json                   # project settings (git)
.claude/settings.local.json             # local (gitignore)
managed-settings.json                   # enterprise
~/.claude/CLAUDE.md · ./CLAUDE.md · ./CLAUDE.local.md   # pamięć
.claude/rules/*.md                      # reguły (opcjonalnie paths:)
.claude/commands/  ~/.claude/commands/  # własne komendy (starszy format, scalony ze skills)
.claude/agents/    ~/.claude/agents/    # subagenci
~/.claude/agent-memory/                 # pamięć subagentów: zakres user
.claude/agent-memory/                   # pamięć subagentów: zakres project
.claude/agent-memory-local/             # pamięć subagentów: zakres local
.claude/skills/    ~/.claude/skills/    # skills (SKILL.md)
.mcp.json                               # MCP (project scope)
~/.claude.json                          # MCP local/user + stan
~/.claude/projects/<project>/memory/    # auto memory
```

## Modele (listopad 2026)

Aliasy: `sonnet`, `opus`, `haiku`, `fable`, `best`, `opusplan`. W Anthropic API wskazują na Sonnet 5.5, Opus 5.5, Haiku 5.5 i Fable 5.1 - pełne ID: `claude-sonnet-5-5`, `claude-opus-5-5`, `claude-haiku-5-5`, `claude-fable-5-1`. Na Bedrock i Google Cloud `sonnet` to wciąż Sonnet 4.5. Domyślny: Opus 5.5 na Pro, Max, Ultra, Team, Enterprise i w API; Sonnet 4.5 na Microsoft Foundry ([konfiguracja modeli](https://code.claude.com/docs/en/model-config)).

## Ćwiczenie końcowe: 30 minut

Zbuduj własny starter kit. Pięć elementów, po jednym z każdej ważnej lekcji tej sekcji:

1. `CLAUDE.md` z regułami projektu.
2. Jedną własną komendę `/commit`.
3. Jednego subagenta `code-reviewer` z `memory: project`.
4. Jeden hook auto-formatujący po edycji.
5. Jeden serwer MCP w `.mcp.json`.

Potem przejdź pełny cykl Explore → Plan → Code → Commit i zweryfikuj wynik przez `/code-review` oraz subagenta, którego zadaniem jest szukać błędów w Twoim rozwiązaniu.

**Zaliczenie:** wszystkie pięć elementów działa naraz w jednym projekcie, a cykl kończy się commitem, którego nie musiałeś poprawiać ręcznie. To jest Twoja konfiguracja startowa do każdego następnego repozytorium.

**Jeśli nic nie zgrzyta i zostaje czas:** spakuj to wszystko jako plugin i sprawdź, czy da się zainstalować w drugim projekcie jedną komendą.

## Teraz wiesz

- Cała konfiguracja Claude Code mieści się w kilkunastu ścieżkach, które warto znać na pamięć.
- Starter kit z pięciu elementów zamyka wszystko, czego uczyła ta sekcja.
