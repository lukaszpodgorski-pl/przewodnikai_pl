## Który plan jest potrzebny

Claude Code wymaga planu **Pro, Max, Ultra, Team lub Enterprise**, albo konta **Console (API)**. Darmowy plan Claude.ai **nie** obejmuje Claude Code ([cennik](https://claude.com/pricing), [logowanie w dokumentacji](https://code.claude.com/docs/en/authentication)).

**Logowanie kontem Claude (Pro, Max, Ultra, Team, Enterprise):**

```bash
claude              # przy pierwszym starcie otwiera przeglądarkę
claude auth login   # jawne logowanie; --console dla konta Console (rozliczanie API)
claude auth status  # status (JSON; --text dla wersji czytelnej)
claude auth logout
```

W sesji działają odpowiedniki: `/login` i `/logout`.

## Zmienne środowiskowe

Zmienna środowiskowa to nazwana wartość zapisana w systemie albo w profilu terminala, którą programy odczytują przy starcie. Najważniejsza dla Twojego rachunku jest pierwsza w tabeli. Pozostałe przydają się w firmie albo wtedy, gdy korzystasz z Claude przez chmurę Amazon (Bedrock) lub Google (Agent Platform).

| Zmienna | Znaczenie |
| --- | --- |
| `ANTHROPIC_API_KEY` | klucz API (Console). Gdy zgodzisz się go użyć, **ma priorytet nad subskrypcją** - płacisz za faktyczne zużycie (pay-as-you-go) |
| `ANTHROPIC_MODEL` | model główny (alias lub pełne ID) |
| `ANTHROPIC_DEFAULT_MODEL` | domyślny model nowych sesji |
| `ANTHROPIC_DEFAULT_OPUS_MODEL` i pokrewne | do czego rozwijają się poszczególne aliasy |
| `CLAUDE_CODE_SUBAGENT_MODEL` | model dla <Termin id="subagent">subagentów</Termin> (pomocników, którym Claude zleca część zadania w osobnym oknie kontekstowym; więcej w [lekcji o subagentach](/claude-code/subagenci/)) |
| `CLAUDE_CODE_USE_BEDROCK=1` | użyj Amazon Bedrock (auth przez AWS; `ANTHROPIC_API_KEY` ignorowany) |
| `CLAUDE_CODE_USE_VERTEX=1` | użyj Google Cloud (Agent Platform, Vertex AI) |
| `AWS_REGION`, `ANTHROPIC_VERTEX_PROJECT_ID`, `CLOUD_ML_REGION` | konfiguracja providerów chmurowych |

:::danger[Klucz API wygrywa z subskrypcją]
Gdy ustawiony jest `ANTHROPIC_API_KEY`, Claude Code raz pyta, czy go użyć, i zapamiętuje wybór. Jeśli kiedyś padła zgoda, każda kolejna sesja idzie na rozliczenie API i może wygenerować nieoczekiwane koszty. Wybór zmienisz w `/config` (przełącznik "Use custom API key"). W trybie `-p` klucz jest używany zawsze, bez pytania. Aktywną metodę sprawdzisz przez `/status`.
:::

**Amazon Bedrock:** kreator `/setup-bedrock`, ukryty w menu dopóki nie ustawisz `CLAUDE_CODE_USE_BEDROCK=1`. Wymaga zatwierdzenia "use case" w konsoli Bedrock.

**Google Cloud Agent Platform:** kreator `/setup-vertex`, analogicznie po `CLAUDE_CODE_USE_VERTEX=1`.

**Token długoterminowy do CI:** `claude setup-token` - wymaga subskrypcji, wypisuje token OAuth do `CLAUDE_CODE_OAUTH_TOKEN`.

## Monitorowanie zużycia

- `/usage` - koszt sesji, limity planu, statystyki (aliasy `/cost`, `/stats`). **Od wersji 2.1.243** zaplanowane zadania `/loop` mają tu osobne wiersze - ile razy się uruchomiły i ile tokenów zużyły. Wreszcie widać, co kosztuje która automatyzacja.
- `/context` - co zajmuje <Termin id="okno-kontekstowe">okno kontekstowe</Termin> (siatka, ostrzeżenia).
- `/status` - wersja, model, konto, łączność, aktywna metoda uwierzytelnienia.
- Limity claude.ai: przy uderzeniu w limit Claude Code może **automatycznie poczekać** na reset i kontynuować (`/rate-limit-options`, ustawienie `autoContinueAtUsageLimit`).

## Ćwiczenie: 5 minut

1. Uruchom `/status` i sprawdź, jaką masz aktywną metodę uwierzytelnienia.
2. Uruchom `/usage` i zapisz koszt bieżącej sesji.
3. Uruchom `/context` i zapisz procent zapełnienia okna kontekstowego.

**Zaliczenie:** masz trzy liczby na kartce i wiesz, czy płacisz z subskrypcji, czy z API. Jeśli to drugie, a nie tak miało być, znasz już przyczynę.

**Jeśli nic nie zgrzyta i zostaje czas:** wpisz `echo $ANTHROPIC_API_KEY` (PowerShell: `$env:ANTHROPIC_API_KEY`) i sprawdź, czy zmienna nie siedzi w Twoim profilu shella z jakiegoś dawnego eksperymentu.

## Teraz wiesz

- Claude Code nie działa na darmowym planie - potrzebna jest subskrypcja albo konto API.
- Zaakceptowany `ANTHROPIC_API_KEY` przebija subskrypcję i to najczęstsza przyczyna niespodzianek na rachunku.
- `/status`, `/usage` i `/context` to trzy komendy, od których zaczynasz każdą diagnozę kosztów.
