## Konfiguracja terminala

`/terminal-setup` ustawia `Shift+Enter` jako nową linię w VS Code, Cursor, Devin Desktop, Zed i Alacritty starszym niż 0.16. W Ghostty, Kitty, iTerm2, WezTerm, Warp, Terminal.app i Windows Terminal `Shift+Enter` działa od razu. W każdym terminalu nową linię wstawisz też przez `Ctrl+J`.

Na macOS ustaw Option jako Meta, żeby działały skróty z klawiszem Option: w iTerm2 Settings → Profiles → Keys → Left/Right Option = "Esc+", w Terminal.app "Use Option as Meta Key".

**Powiadomienia:** w Ghostty, Kitty i iTerm2 Claude Code sam wysyła powiadomienie systemowe, gdy skończy zadanie albo czeka na Twoją zgodę. W innych terminalach ustaw w settings `"preferredNotifChannel": "terminal_bell"` (dźwięk terminala) albo skonfiguruj hook `Notification` (patrz [lekcja o hookach](/claude-code/hooks/)). `FORCE_HYPERLINK=1` włącza klikalne linki, gdy terminal je obsługuje, a Claude Code tego nie wykrył.

## IDE

Komenda `/ide` zarządza integracją i pokazuje status, a `--ide` łączy automatycznie przy starcie.

Rozszerzenie **VS Code** ma własny panel czatu i Focus view, jest też plugin **JetBrains**. Obie to nakładki na ten sam silnik - piszą do `~/.claude/`.

## tmux i wiele instancji

tmux (program do dzielenia terminala na okna, patrz [Interfejs i skróty](/claude-code/interfejs-i-skroty/)) utrzymuje też sesje po zamknięciu okna. Wymaga trzech linii w `~/.tmux.conf`. Bez nich `Shift+Enter` wysyła wiadomość zamiast łamać linię, a powiadomienia nie docierają:

```bash
set -g allow-passthrough on
set -s extended-keys on
set -as terminal-features 'xterm*:extkeys'
```

Kilka zadań naraz poprowadzisz na trzy sposoby:

- **osobne terminale i worktree** (osobna kopia robocza repozytorium, patrz [Git i GitHub](/claude-code/git-i-github/)) - dwie sesje nie edytują tych samych plików;
- **sesje w tle** (`claude --bg`; lista: `claude agents` - mimo nazwy to lista sesji w tle, nie subagentów z [lekcji 11](/claude-code/subagenci/); powrót do sesji: `claude attach <id>`) - Claude pracuje, a Ty masz wolny terminal;
- **agent teams** - zespół współpracujących agentów, funkcja eksperymentalna włączana zmienną `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`. Z tmux współpracuje przez tryb `--teammate-mode tmux`.

## Terminal, desktop i telefon

Trzy kierunki przenoszenia sesji:

- **`/desktop`** - z terminala do aplikacji desktop (wymaga macOS albo Windows x64 i subskrypcji Claude). Przydatne, gdy chcesz zobaczyć diffy i podgląd na żywo obok siebie.
- **`/resume` w aplikacji desktop** - kierunek odwrotny. Otwiera picker sesji terminalowych pogrupowanych po dniach, z folderem i gałęzią oraz podglądem miejsca, w którym skończyłeś. Działa też dla sesji już zamkniętych i kontynuuje ten sam transkrypt.
- **Remote Control** - uruchom na komputerze **`claude remote-control`** (skrót: `claude rc`). Terminal pokaże adres sesji, a spacja wyświetli kod QR. Zeskanuj go telefonem albo otwórz aplikację Claude, stuknij **Code** i znajdź sesję na liście - sesje Remote Control mają ikonę komputera. Claude pracuje dalej **na Twoim komputerze**, z jego plikami, serwerami MCP i narzędziami. Sensowne, gdy chcesz prowadzić zadanie, będąc z dala od biurka. Działa na planach Pro, Max, Ultra, Team i Enterprise, nie z kluczem API ([dokumentacja Remote Control](https://code.claude.com/docs/en/remote-control)).

Wymaga aktualizacji do najnowszej wersji po obu stronach. Nazwa z `/rename` i kolor z `/color` są wtedy widoczne także na claude.ai/code.

## Ćwiczenie: 5 minut

1. Uruchom `/terminal-setup`.
2. Uruchom `/ide` i sprawdź status integracji.
3. Odpal `claude remote-control` (skrót: `claude rc`) w katalogu testowego repozytorium i otwórz sesję w aplikacji Claude na telefonie - przez kod QR albo z listy w zakładce Code.

**Zaliczenie:** `Shift+Enter` łamie linię w Twoim edytorze, a w aplikacji na telefonie widzisz swoją sesję na liście. Punkt trzeci jest opcjonalny, jeśli nie masz aplikacji mobilnej.

**Jeśli nic nie zgrzyta i zostaje czas:** nazwij sesję przez `/rename`, nadaj jej kolor przez `/color` i sprawdź, czy oba zostały po przeniesieniu na desktop.

## Teraz wiesz

- `/terminal-setup` załatwia większość drobiazgów, które inaczej irytują codziennie.
- Wtyczka IDE i CLI to jeden silnik, nie dwa różne narzędzia.
- Sesja nie jest przywiązana do terminala - przenosisz ją na desktop i sterujesz z telefonu.
