## Podstawowe komendy

```bash
claude                              # sesja interaktywna
claude "explain this project"       # sesja z promptem początkowym
claude -p "explain this function"   # tryb print (non-interactive), potem wyjście
cat logs.txt | claude -p "explain"  # potokowanie treści
claude -c                           # kontynuuj ostatnią rozmowę w tym katalogu
claude -c -p "Check for type errors" # kontynuacja przez SDK
claude -r "auth-refactor" "Finish this PR"  # wznów sesję po ID lub nazwie
```

## Podkomendy CLI

`claude update`, `claude install [version]`, `claude auth login|logout|status`, `claude doctor`, `claude mcp ...`, `claude mcp login|logout <name>`, `claude plugin ...`, `claude agents`, `claude attach <id>`, `claude logs <id>`, `claude stop <id>`, `claude respawn <id>`, `claude rm <id>`, `claude setup-token`, `claude project purge [path]`, `claude gateway`, `claude ultrareview [target]`, **NOWE:** `claude rc` (Remote Control - patrz lekcja o [terminalu, IDE i urządzeniach](/claude-code/terminal-ide-urzadzenia/)).

Literówka w podkomendzie nie kończy się błędem bez wyjaśnienia - Claude Code podpowiada najbliższą, na przykład `claude udpate` → "Did you mean claude update?".

| `--resume`, `-r` | wznów sesję po ID lub nazwie, albo pokaż picker |

| `--model` | model sesji (alias lub pełne ID) |
| `--fallback-model` | model zapasowy przy przeciążeniu lub niedostępności |
| `--effort` | poziom rozumowania: `low`, `medium`, `high`, `xhigh`, `max`, `ultracode` |
| `--output-format` | `text` (domyślnie), `json`, `stream-json` (print mode) |
| `--input-format` | `text`, `stream-json` (print mode) |
| `--include-partial-messages` | częściowe zdarzenia streamu (wymaga `--print` i `stream-json`) |

| `--max-budget-usd` | limit wydatków USD na wywołania API (print mode) |

| `--setting-sources` | źródła settings do wczytania: `user,project,local` |

| `--name`, `-n` | nazwa sesji (widoczna w `/resume`) |
| `--worktree`, `-w` | start w izolowanym git worktree |
| `--tmux` | utwórz sesję tmux dla worktree (wymaga `--worktree`) |
| `--bg`, `--background` | start jako background agent |

| `--chrome`, `--no-chrome` | integracja Chrome (automatyzacja przeglądarki) |

## Tryb restricted w szczegółach

**NOWE v2.1.248.** Po starcie `claude --restricted` Claude **nie może uruchamiać komend, wykonywać kodu ani pobierać treści z sieci**. Narzędzia plikowe działają wyłącznie w katalogu roboczym, a settings użytkownika i projektu są ignorowane.

To tryb pod współdzielone maszyny i harnessy ewaluacyjne - wszędzie tam, gdzie chcesz pokazać komuś narzędzie bez oddawania mu maszyny.

:::caution[--help nie jest pełną listą]
`claude --help` **nie** listuje wszystkich flag. Brak flagi w `--help` nie znaczy, że ona nie istnieje. Kanonicznym źródłem jest [CLI reference w dokumentacji](https://docs.claude.com/en/docs/claude-code/cli-reference).
:::

## Ćwiczenie: 5 minut

1. Uruchom `claude -p "wypisz nazwy funkcji w tym pliku" --output-format json < ścieżka/do/pliku`.
2. Obejrzyj strukturę JSON w odpowiedzi.
3. Znajdź pola `session_id`, koszt i wynik.

**Zaliczenie:** masz w terminalu JSON, w którym potrafisz wskazać identyfikator sesji i koszt. To jest dokładnie to, co Twój skrypt albo pipeline CI będzie parsował.

**Jeśli nic nie zgrzyta i zostaje czas:** powtórz to samo z `--max-turns 1` i porównaj wynik. Zobaczysz, gdzie kończy się jedna tura agenta.

## Teraz wiesz

- `-p` zamienia Claude Code w narzędzie skryptowalne, `-c` i `-r` wracają do rozmowy.
- Flagi dzielą się na trzy rodziny: model i rozumowanie, uprawnienia, format wejścia i wyjścia.
- `--help` bywa niepełne, więc kanonem jest dokumentacja, nie terminal.
