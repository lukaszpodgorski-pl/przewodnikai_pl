Część flag dotyczy rzeczy z dalszych lekcji - subagentów, hooków, MCP, skilli. Jeśli nazwa nic Ci nie mówi, pomiń ją. Wrócisz tu po lekcji o [skills i plugins](/claude-code/skills-i-plugins/) i wtedy cała tabela będzie czytelna.

## Podstawowe komendy

```bash
claude                                    # sesja interaktywna
claude "wyjaśnij ten projekt"             # sesja z promptem początkowym
claude -p "wyjaśnij tę funkcję"           # tryb print (non-interactive), potem wyjście
cat logs.txt | claude -p "wyjaśnij"       # potokowanie treści
claude -c                                 # kontynuuj ostatnią rozmowę w tym katalogu
claude -c -p "sprawdź błędy typów"        # kontynuacja w trybie print (skrypty)
claude -r "auth-refactor" "dokończ ten PR"  # wznów sesję po ID lub nazwie
```

## Podkomendy CLI

Podkomenda to drugie słowo po `claude`, które zamiast rozmowy uruchamia konkretne narzędzie:

- `claude update` - aktualizuje Claude Code do najnowszej wersji.
- `claude install [version]` - instaluje lub reinstaluje wybraną wersję.
- `claude auth login|logout|status` - logowanie, wylogowanie i sprawdzenie, na jakie konto jesteś zalogowany.
- `claude doctor` - diagnostyka instalacji bez uruchamiania sesji.
- `claude mcp ...` (w tym `claude mcp login|logout <name>`) i `claude plugin ...` - zarządzanie serwerami MCP i pluginami, każde ma swoją lekcję.
- `claude agents`, `claude attach <id>`, `claude logs <id>`, `claude stop <id>`, `claude respawn <id>`, `claude rm <id>` - podgląd i obsługa sesji, które działają w tle.
- `claude setup-token` - długoterminowy token do skryptów i CI.
- `claude purge [path]` - usuwa wszystkie lokalne dane Claude Code dla projektu (stara nazwa `claude project purge` nadal działa).
- `claude remote-control` (skrót: `claude rc`) - Remote Control, patrz lekcja o [terminalu, IDE i urządzeniach](/claude-code/terminal-ide-urzadzenia/).
- `claude ultrareview [target]` - pogłębiony przegląd kodu uruchamiany z terminala.
- `claude gateway` - narzędzie dla administratorów firm, na start możesz je pominąć.

Literówka w podkomendzie nie kończy się błędem bez wyjaśnienia - Claude Code podpowiada najbliższą, na przykład `claude udpate` → "Did you mean claude update?".

## Najważniejsze flagi CLI

Na start wystarczą Ci cztery: `-p`, `-c`, `-r` i `--model`. Resztę sprawdzaj, gdy będzie potrzebna.

| Flaga | Opis |
| --- | --- |
| `--print`, `-p` | tryb print (bez interaktywności), do skryptów i SDK |
| `--continue`, `-c` | wczytaj ostatnią rozmowę w bieżącym katalogu |
| `--resume`, `-r` | wznów sesję po ID lub nazwie, albo pokaż picker |
| `--fork-session` | przy wznawianiu zacznij nową, osobną kopię rozmowy (oryginał zostaje nietknięty) |
| `--model` | model sesji (alias lub pełne ID) |
| `--fallback-model` | model zapasowy przy przeciążeniu lub niedostępności |
| `--effort` | poziom wysiłku: `low`, `medium`, `high`, `xhigh`, `max`; osobno `ultracode` - to nie kolejny poziom, tylko osobne ustawienie do wieloetapowych przebiegów (`--effort ultracode` włącza je i ustawia poziom `xhigh`, patrz [Kontekst i koszty](/claude-code/kontekst-i-koszty/)) |
| `--output-format` | `text` (domyślnie), `json`, `stream-json` (print mode) |
| `--input-format` | `text`, `stream-json` (print mode) |
| `--include-partial-messages` | częściowe zdarzenia streamu (wymaga `--print` i `stream-json`) |
| `--verbose` | pokaż pełny przebieg pracy, krok po kroku |
| `--max-turns` | limit tur agentowych (print mode) |
| `--max-budget-usd` | limit wydatków USD na wywołania API (print mode) |
| `--permission-mode` | `default`, `acceptEdits`, `plan`, `auto`, `dontAsk`, `bypassPermissions` (`manual` = alias `default`) |
| `--dangerously-skip-permissions` | pomiń prompty uprawnień (odpowiednik `bypassPermissions`) |
| `--allow-dangerously-skip-permissions` | dodaj `bypassPermissions` do cyklu Shift+Tab bez startu w nim |
| `--allowedTools`, `--allowed-tools` | narzędzia bez promptu (reguły w składni permission) |
| `--disallowedTools`, `--disallowed-tools` | reguły zakazu - narzędzia lub komendy, których Claude nie może użyć |
| `--tools` | ogranicz dostępne wbudowane narzędzia (`""`, `"default"`, `"Bash,Edit,Read"`) |
| `--add-dir` | dodatkowe katalogi robocze do odczytu i edycji |
| `--mcp-config` | wczytaj serwery MCP z plików lub stringów JSON |
| `--strict-mcp-config` | używaj wyłącznie serwerów z `--mcp-config` |
| `--agents` | zdefiniuj [subagentów](/claude-code/subagenci/) w JSON na czas sesji |
| `--agent` | uruchom całą sesję jako dany subagent |
| `--append-system-prompt` | dopisz tekst do domyślnego system promptu |
| `--append-system-prompt-file` | dopisz zawartość pliku do system promptu |
| `--system-prompt` | zastąp całą instrukcję startową Claude (system prompt, czyli ukryte polecenia, z którymi rusza każda sesja) własnym tekstem |
| `--system-prompt-file` | zastąp system prompt zawartością pliku |
| `--append-subagent-system-prompt` | dopisz tekst do promptu każdego subagenta (print mode) |
| `--settings` | ścieżka do pliku settings JSON lub inline JSON (nadpisuje klucze) |
| `--setting-sources` | źródła settings do wczytania: `user,project,local` |
| `--session-id` | użyj konkretnego UUID sesji |
| `--name`, `-n` | nazwa sesji (widoczna w `/resume`) |
| `--worktree`, `-w` | start w izolowanym git worktree (osobna kopia robocza repozytorium, patrz [lekcja o Gicie](/claude-code/git-i-github/)) |
| `--tmux` | utwórz sesję tmux dla worktree (wymaga `--worktree`) |
| `--bg`, `--background` | start jako background agent |
| `--exec` | uruchom komendę shell jako background job (z `--bg`) |
| `--ide` | połącz automatycznie z IDE przy starcie |
| `--chrome`, `--no-chrome` | integracja Chrome (automatyzacja przeglądarki) |
| `--bare` | tryb minimalny: pomija auto-discovery hooków, skilli, pluginów, MCP i CLAUDE.md - do skryptów i CI |
| `--safe-mode` | wyłącz wszystkie Twoje dodatki (CLAUDE.md, skille, pluginy, hooki, MCP) - do szukania, co psuje konfigurację |
| `--restricted` | tryb ograniczony - patrz niżej |
| `--debug`, `--debug-file <path>` | tryb debug, zapis logów debug do pliku |
| `--json-schema` | walidowane wyjście JSON wg schematu (print mode) |
| `--replay-user-messages` | dla integracji: odeślij na wyjście wiadomości przyjęte na wejściu |
| `--disable-slash-commands` | wyłącz wszystkie skille i komendy dla sesji |
| `--version`, `-v` | wersja |

## Tryb restricted w szczegółach

**Od wersji 2.1.248.** Po starcie `claude --restricted` Claude **nie może uruchamiać komend, wykonywać kodu ani pobierać treści z sieci**. Narzędzia plikowe działają wyłącznie w katalogu roboczym, a ustawienia użytkownika i projektu są ignorowane.

To tryb pod współdzielone maszyny i automatyczne testy narzędzia - wszędzie tam, gdzie chcesz pokazać komuś narzędzie bez oddawania mu maszyny.

:::caution[--help nie jest pełną listą]
`claude --help` **nie** listuje wszystkich flag. Brak flagi w `--help` nie znaczy, że ona nie istnieje. Kanonicznym źródłem jest [CLI reference w dokumentacji](https://code.claude.com/docs/en/cli-reference).
:::

## Ćwiczenie: 5 minut

1. Uruchom `claude -p "wypisz nazwy funkcji w pliku app.js" --output-format json`. Zamień `app.js` na nazwę dowolnego pliku z Twojego projektu - Claude sam go przeczyta.
2. Obejrzyj strukturę JSON w odpowiedzi.
3. Znajdź pola `session_id` (identyfikator sesji), `total_cost_usd` (szacowany koszt) i `result` (odpowiedź).

**Zaliczenie:** masz w terminalu JSON, w którym potrafisz wskazać identyfikator sesji i koszt. To jest dokładnie to, co Twój skrypt albo pipeline CI będzie parsował.

**Jeśli nic nie zgrzyta i zostaje czas:** powtórz to samo z `--max-turns 1` i porównaj wynik. Zobaczysz, gdzie kończy się jedna tura agenta.

## Teraz wiesz

- `-p` zamienia Claude Code w narzędzie skryptowalne, `-c` i `-r` wracają do rozmowy.
- Najczęściej sięgniesz po flagi z trzech grup: model i poziom wysiłku, uprawnienia, format wejścia i wyjścia.
- `--help` bywa niepełne, więc kanonem jest dokumentacja, nie terminal.

**Następny krok:** [Interfejs i skróty klawiszowe](/claude-code/interfejs-i-skroty/) - to, co dzieje się już w środku sesji, od `Esc` po wklejanie obrazów.
